## 5. ⚠⚠ Hard-won lessons — each one cost money or time in the last two days

1. **Never read `✅` on an output count equal to the cap.** Check `stop_reason`. `DX-69` (E-02) and
   `DX-84` (7 of 8 Stage-A calls, $3.22 wasted, reported as `8/8`) both looked successful.
2. **"It parsed" ≠ "it is complete."** A truncated `J-01` parsed as JSON while missing `why`. The
   judgement runner now checks the schema's required fields.
3. **The judgement runner bypasses `Gateway.call`.** Any gateway guarantee (`GW-23` truncation, retry,
   budget) must be re-implemented there or it does not exist. Output budget comes from
   `call.py::MAX_TOKENS` — never add a literal.
4. **Estimates from broken runs are broken prices.** Stage A is **~$4.9** at k=1, not $3.7. Rubric
   blocks want 9–14k output tokens. `K_RUNS`=3 ≈ $14.6. Use 3 chars/token for filing text.
5. **A single re-record cannot validate a prompt change** — run-to-run variance is large (`DX-75`:
   38/63/~55/48 items on one prompt). Don't attribute a delta without k>1.
6. **Assert what the DOCUMENT fixes, not what the model authors** (`DX-73`/`74`/`77`): period starts
   the filing never states, qualifiers the model invents, quote boundaries it chooses. Spans were
   stable 4/4; value text was not.
7. **Mutation-test every new guard, including its CALLER.** Twice a guard's pure function was tested
   and its use was not (`DX-82`), and once a test read a registry copy while the factory held another.
8. **A list pinned to what existed when written drifts** (`DX-72`, `DX-88`) — derive choices/versions.
9. **Measure before specifying.** Three plan corrections in two days came from checking a list against
   the code instead of trusting a summary (the E-block dependency list, "17 selectors" → 6, "10 of 13" → 9 of 11).
